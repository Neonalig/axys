# Testing Axys

What is checked automatically, what has to be listened to, and the performance envelope the
numbers are measured against. `docs/design_bible.md` section 13 is the requirement; this is how it
is met.

## Running everything

```bash
npm run check
```

That runs `cargo fmt --check`, `cargo clippy -D warnings`, `tsc --noEmit`, ESLint, Prettier, then
the Rust, TypeScript and integration suites. `npm run test` runs only the suites.

Individual suites:

```bash
cargo test --workspace
npx vitest run
node fixtures/generate.mjs
```

## DSP fixtures

`fixtures/` is generated by `fixtures/generate.mjs` and covers every case design bible 13.2 names:
sustained vowels, vibrato, drift, scoops and falls, slides, rapid transitions, breathy material,
unvoiced consonants, octave ambiguity, low confidence, and MIDI with tempo and meter changes.
Everything is synthesised, so it is short, deterministic and redistributable under the project
licence.

`tests/dsp-quality.test.ts` runs the real engine over these and asserts measurable properties:

- **F0 accuracy.** Detected pitch on `sustained-vowel.wav` is within 5 cents of the synthesised
  value; on `slide.wav` the detected track is monotone and matches the synthesised glissando within
  20 cents.
- **Modulation.** Detected vibrato depth on `vibrato.wav` is within 15 percent of the synthesised
  depth, and drift on `drift.wav` is tracked without being read as vibrato.
- **Octave stability.** No frame of `octave-ambiguity.wav` lands a full octave from the truth.
- **Voicing.** Sibilant and plosive spans of `consonants.wav` are classified unvoiced; the vowels
  between them are voiced.
- **Pitch fidelity after transformation.** Rendering a plan that moves a note by +3, +7 and -5
  semitones and re-analysing the output gives F0 within 15 cents of the target.
- **Continuity.** No rendered output contains a sample-to-sample step larger than the largest step
  in the source scaled by the pitch ratio, which is the numerical form of "no clicks at edit
  boundaries".
- **Transients.** After a 1.4x time expansion of `consonants.wav`, each plosive still appears as a
  single energy peak in the output, at the position the time map predicts, within 10 ms.
- **Peak and clipping.** Export reports the true peak, and a plan that would exceed full scale is
  reported rather than silently wrapped.
- **Determinism.** The same project rendered twice is bit-identical, and a render split into
  arbitrary blocks is bit-identical to a single-call render.

These are numerical proxies. They catch regressions; they do not establish that something sounds
good.

## Level-matched listening procedure

Run this before accepting any change to `analysis/f0.rs`, `dsp/psola.rs`, `dsp/formant.rs` or
`target.rs`. It is the only way to judge the qualities in design bible 7.3 that numbers cannot
settle.

1. **Prepare.** Closed-back headphones or monitors in a quiet room. Fixed system volume for the
   whole session; do not adjust it between comparisons.
2. **Level match.** Export both the original and the processed render. Measure the integrated
   loudness of each over the same span and apply a gain offset to the processed file so the two
   match within 0.2 LU. Loudness differences are heard as quality differences, so skipping this
   invalidates the result.
3. **Blind the comparison.** Have a second person, or a script, randomise which file plays as A and
   which as B, and record the mapping separately.
4. **Audition.** For each fixture and for at least one real vocal, loop a 4 to 8 second span.
   Switch between A and B at least six times. Score each of the following 1 to 5, where 3 means "I
   could ship this":
   - naturalness of the voice;
   - stability of the vowel, meaning no warble or flutter;
   - intelligibility of consonants;
   - absence of clicks, zips or phase smear at edit boundaries;
   - whether the intended musical change actually happened.
5. **Record.** Write the scores, the build revision and the settings into the pull request. Any
   score of 2 or below on a fixture that previously scored 3 or above is a regression and blocks
   the change.
6. **Escalate.** For a change that alters the default DSP path, repeat with a second listener and a
   different vocal before merging.

Known material where a low score is expected rather than a regression is listed under Known
limitations in `docs/decisions.md`. Update that list rather than quietly accepting a new artefact.

## Performance envelope

Axys does not claim universal realtime performance. These are the declared conditions.

**Baseline hardware.** A 2020-or-later x86-64 laptop, four physical cores, 8 GB RAM, integrated
graphics. Nothing here requires a discrete GPU.

**Baseline browsers.** Current Chrome, Edge and Firefox on desktop, and Safari 17 or newer.

**Representative project.** One mono vocal of four minutes at 48 kHz, one MIDI guide of about 200
notes, analysis at a 5 ms hop, and continuous playback while the editor redraws.

**Targets on that baseline.**

| Measure                                     | Target                                    |
| ------------------------------------------- | ----------------------------------------- |
| Editor frame time during playback           | under 16 ms at the 95th percentile        |
| Pointer-to-preview latency on a drag        | under 50 ms                               |
| Plan recompile after one edit               | under 30 ms                               |
| Full analysis of the representative project | under 25 s, chunked and cancellable       |
| Analysis cancellation                       | takes effect within 250 ms                |
| Audio callback headroom                     | render of a 128-sample block under 1.0 ms |
| Playback underruns                          | none over a five-minute continuous play   |
| Peak memory                                 | under 700 MB                              |

**How to measure.** Open the app, load `fixtures/audio/phrase.wav` repeated to four minutes, and
use the browser performance profiler for frame time and the Diagnostics panel for the audio-thread
figures, which the worklet reports each second. Analysis timing is printed by the analysis worker
in development builds.

**Degradation.** When a target is missed the app says so rather than stuttering silently: the
worklet reports underruns to the main thread, which raises a toast and drops the preview to a
lower-cost path while keeping the same edit interpretation. An unavailable optional capability
(WebGPU, OPFS sync handles, threading) never blocks operation and is reported in Diagnostics.

## Core workflow acceptance

`tests/workflow-acceptance.test.ts` drives the six steps in design bible 13.4 through the real
engine, without a browser:

1. Import `fixtures/audio/phrase.wav`, analyse, and assert a navigable pitch track and more than
   one provisional blob.
2. Move one boundary and assert the pitch track is unchanged, meaning nothing reanalysed.
3. Move a note centre, reshape its tail with anchors, change its timing, and assert each affects
   only what it should.
4. Render the looped region twice, processed and bypassed, and assert they differ audibly but
   share length.
5. Serialise, reopen, and assert the render is bit-identical.
6. Export WAV, decode it back, and assert its F0 and onset positions match the active edits.

## MIDI workflow acceptance

`tests/midi-acceptance.test.ts` drives design bible 13.5:

1. Import `fixtures/midi/melody.mid`, list tracks, select one, and assert its notes land on the
   right seconds.
2. Anchor a known onset to a time and assert the offset moves the guide, not the audio.
3. Introduce a tempo error, and assert `measure_drift` separates the constant offset from the
   growing drift.
4. Load `fixtures/midi/tempo-change.mid` and `meter-change.mid` and assert bar lines, beats and the
   playhead readout stay correct through both.
5. Switch between visual-only, pitch-only, timing-only and combined guidance and assert the plan
   changes in exactly the expected dimension each time.
6. Override one mapping and assert the source analysis and the manual curves survive it.
